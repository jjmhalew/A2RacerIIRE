# COVERAGE.md - which code of the original has been analysed

How much of the three programs on the CD (`spel.dat` the race, `menu.dat` the menus, `a2_II.exe` the launcher) is named
somewhere in this repository, and the list of functions nobody has looked at yet. Use it to find what is left to
analyse; update it after every round of analysis.

## How it is made
`python tools/coverage.py --write` (needs the CD's files in `extract/data`, like `tools/disasm.py`) rewrites the part
below the generated marker. `--min N` sets the smallest function in the list (default 30 instructions); without
`--write` it only prints.

- **Functions** are those of `tools/disasm.py`: call targets, `push ebp; mov ebp, esp` prologues, the entry point and
  pointers in `.data`/`.rdata` (vtables, callback tables).
- A function is **covered** when any address inside it (`0x4xxxxx`) appears in `docs/*.md`, `docs/names/*.txt`,
  `src/*.[ch]` or `tools/*.py`. This file and `SOURCES_raw.txt` do not count. Covered means someone has looked at the
  function. It does not mean the port does the same thing.
- `spel.dat` and `menu.dat` both load at `0x400000`, so each address is credited to one program. A word `menu`,
  `spel` or `a2_II` just before the address decides. Otherwise it goes to the only program whose names file has it,
  and otherwise to the file's own program: `names/menu_*`, `MENU.md` and `src/menu*` count for menu.dat,
  `names/a2_*` for a2_II.exe, and everything else for spel.dat. Write `menu 0x4xxxxx` in a doc that is not about the
  menus.
- **Areas** follow [ANALYSE.md](ANALYSE.md) "The code". In spel.dat the game code runs up to `0x435000`, the 3D library
  `win3ddp` up to `0x464000`, then the 2D library `winlib`. The MSVC C runtime is not counted: in spel.dat from
  `0x471000`, in a2_II.exe from `0x401520`, in menu.dat (roughly) from the entry point. The port replaces DirectX, the
  Windows parts of `winlib` and the C runtime, so a gap there often needs no analysis.
- **Source file** is the original `.cpp` of the nearest assert or debug string at or before the function. MSVC keeps
  the functions of one object file together, so this is usually right, but a file without strings is counted under
  the one before it.
